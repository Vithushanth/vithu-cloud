Containerised API on ECS Fargate

The standard container pattern, built end to end: write an app, package it, push it to a registry and run it behind a load balancer with no servers to manage.

Built with
Docker, ECR, ECS Fargate, Application Load Balancer, VPC, CloudFormation, CloudWatch Logs, Python (Flask)
View the code on GitHub

How it works

  1. deploy.sh builds the Docker image and pushes it to an ECR repository, which scans it for known vulnerabilities.
  2. CloudFormation creates a VPC with two public subnets in different Availability Zones.
  3. An Application Load Balancer accepts HTTP from the internet and forwards it to the containers on port 8080.
  4. ECS Fargate runs the container. There is no EC2 instance to patch.
  5. The load balancer calls /health every 15 seconds and only sends traffic to containers that answer.
  6. On a new deploy, ECS starts the new version, waits for it to pass health checks, then stops the old one. If it fails, the circuit breaker rolls back.

Why I built it

My other projects are serverless. Most companies also run containers, so I wanted to build that pattern myself instead of only reading about it.

What I learned

  • The task execution role is what ECS needs to start the container, such as pulling the image and writing logs. A task role is what the app itself may do. They are separate on purpose.
  • Fargate uses awsvpc networking, so each task gets its own network interface and the target group has to use ip targets.
  • Health checks, minimum healthy percent and the circuit breaker together give a rolling deployment that cannot take the service down.

Containers accept traffic only from the load balancer

TaskSecurityGroup:
  Type: AWS::EC2::SecurityGroup
  Properties:
    GroupDescription: Allow traffic to the containers only from the load balancer
    VpcId: !Ref Vpc
    SecurityGroupIngress:
      - IpProtocol: tcp
        FromPort: 8080
        ToPort: 8080
        SourceSecurityGroupId: !Ref LoadBalancerSecurityGroup

The load balancer and the task are billed by the hour, so I deploy this for demos and remove it afterwards with destroy.sh.

What I would add next

  • HTTPS on the load balancer with an ACM certificate
  • Tasks in private subnets, pulling images through VPC endpoints
  • Auto scaling on CPU and a GitHub Actions pipeline to build and deploy on push
