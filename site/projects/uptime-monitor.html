Uptime monitor and status page

Monitoring from the outside, the way a visitor sees the site, with a public status page that needs no API and no database.

Built with
Lambda (Python 3.12), EventBridge, S3, CloudFront, SNS, AWS SAM
View the code on GitHubOpen the live status page

How it works

  1. EventBridge runs the function every five minutes.
  2. The function requests each URL and records the HTTP status and the response time.
  3. It loads the previous results, adds the new check and keeps the last 24 hours.
  4. It writes status/status.json to the website bucket with a 60-second cache lifetime.
  5. If a site has changed state since the last check, it publishes to SNS, which sends an email.
  6. The status page on this site reads the file and draws the history.

Why I built it

My monitoring project watches an EC2 instance from the inside. This one watches from the outside. I also wanted a status page with as few moving parts as possible.

What I learned

  • The function can read and write one prefix in the bucket, status/*, and nothing else.
  • Alerting on the change of state keeps the noise down. A long outage sends one email, not one every five minutes.
  • A short Cache-Control lifetime stops CloudFront serving stale results.

Alert on the change, not on every failure

# tell someone only when the state changes, not on every failed check
if topic and "up" in before and before["up"] != up:
    state = "is back up" if up else "is DOWN"
    sns.publish(
        TopicArn=topic,
        Subject=f"{url} {state}"[:100],
        Message=f"{url} {state} at {now.isoformat()} "

    )

The tests fake S3 and SNS with moto and walk a site through up, down, still down and recovered, checking exactly two alerts are sent.

What I would add next

  • Checks from a second region, to tell a site outage from a regional problem
  • TLS certificate expiry warnings
  • CloudWatch Synthetics for full browser checks
