Cost and security guardrail

A report that arrives every Monday with the forgotten resources and risky settings in an AWS account, so the cleanup gets done.

Built with
Lambda (Python 3.12), boto3, EventBridge, SNS, IAM, AWS SAM, pytest with moto
View the code on GitHub

How it works

  1. EventBridge runs the function every Monday at 08:00 UTC.
  2. It lists EBS volumes that are not attached to anything and Elastic IPs that are not associated with anything.
  3. It lists EC2 instances missing the required tags, which are Owner and Project by default.
  4. It finds security groups that allow SSH or RDP from 0.0.0.0/0 or ::/0.
  5. It checks every S3 bucket for all four public access block settings.
  6. It emails the findings through SNS and writes the same report to CloudWatch Logs.

Why I built it

On a service desk, small things left alone become incidents. Cloud accounts are the same: a forgotten volume keeps billing and an open SSH rule keeps waiting. I wanted the cleanup list to arrive without anyone having to go looking.

What I learned

  • Paginators, so every check still works in an account with hundreds of resources.
  • How to tell an "all traffic" rule from a port range when reading security group rules.
  • Testing against fake AWS services with moto. Each check has a test that creates a bad resource and a good one, and proves only the bad one is reported.

A read-only role

Policies:
  # read-only: the function reports problems, it never changes anything
  - Statement:
      - Effect: Allow
        Action:
          - ec2:DescribeInstances
          - ec2:DescribeVolumes
          - ec2:DescribeAddresses
          - ec2:DescribeSecurityGroups
          - s3:ListAllMyBuckets
          - s3:GetBucketPublicAccessBlock
        Resource: "*"
  - SNSPublishMessagePolicy:
      TopicName: !GetAtt ReportTopic.TopicName

Because the role cannot modify anything, the function is safe to run in any account, including production.

What I would add next
