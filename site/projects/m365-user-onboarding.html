Microsoft 365 user onboarding

New starter setup that takes a list and does the same steps every time, with a dry-run mode and a record of what was done.

Built with
PowerShell, Microsoft Graph, Microsoft Entra ID, Microsoft 365
View the code on GitHub

How it works

  1. The script reads starters.csv, one row per new starter.
  2. It signs in to Microsoft Graph and checks there are enough free licences before changing anything.
  3. For each person it creates the account with a random temporary password that must be changed at first sign-in.
  4. It assigns the Microsoft 365 licence and adds the user to each group listed for them.
  5. It writes the result for every row to a dated log file. If one row fails, the rest still run.

Why I built it

At Metro Bank and St John Ambulance I set up new starters by hand in Active Directory and Office 365. It is slow, and it is easy to miss a group. This does the same job from a list, the same way every time.

What I learned

  • How to use ShouldProcess so the script supports -WhatIf. A dry run shows every change without making any.
  • Requesting only the Graph scopes the script needs, the same least-privilege idea as an IAM role.
  • Checking preconditions first. Running out of licences halfway through a batch is worse than refusing to start.

Every change can be previewed

if ($PSCmdlet.ShouldProcess($upn, 'Create user')) {
    $password = New-TemporaryPassword
    $user = New-MgUser -DisplayName "$first $last" `
        -UserPrincipalName $upn -MailNickname $nickname `
        -JobTitle $starter.JobTitle -Department $starter.Department `
        -UsageLocation $UsageLocation -AccountEnabled `
        -PasswordProfile @{
            Password = $password
            ForceChangePasswordNextSignIn = $true
        }
}

Temporary passwords are shown once on screen and are never written to the log file.

What I would add next

  • A matching leaver script that blocks sign-in and removes licences
  • A welcome email to the manager with the start details
  • Running from Azure Automation with a managed identity instead of a signed-in admin
