Monitoring and alerting

Monitoring for an EC2 instance that emails you when something is wrong, defined as code so it can be applied to any instance.

Built with
Terraform, CloudWatch dashboards and alarms, SNS, EC2
View the code on GitHub

How it works

  1. EC2 sends CPU and network metrics to CloudWatch.
  2. A dashboard shows CPU utilisation and network in and out side by side.
  3. An alarm checks average CPU over five-minute periods and fires when it is above 80% for two periods in a row.
  4. The alarm publishes to an SNS topic, both when it fires and when it returns to OK.
  5. SNS emails the subscribed address.

Why I built it

I wanted to learn the observability side of AWS as well as the build side. It is better to hear about a problem from your monitoring than from your users.

What I learned

  • The parts of a CloudWatch alarm: metric, statistic, period, evaluation periods and threshold.
  • SNS separates the alarm from the channel. Adding Slack or PagerDuty later means adding a subscription, with no change to the alarm.
  • How to read a dashboard for patterns before they become incidents.

The alarm definition

resource "aws_cloudwatch_metric_alarm" "high_cpu" {
  alarm_name          = "ec2-high-cpu"
  comparison_operator = "GreaterThanThreshold"
  evaluation_periods  = 2
  metric_name         = "CPUUtilization"
  namespace           = "AWS/EC2"
  period              = 300
  statistic           = "Average"
  threshold           = 80
  alarm_actions       = [aws_sns_topic.alerts.arn]
  ok_actions          = [aws_sns_topic.alerts.arn]
  dimensions = {
    InstanceId = var.instance_id
  }
}

The instance ID and the alert email are variables, so the same code monitors any instance: terraform apply -var="alert_email=you@example.com" -var="instance_id=i-XXXX"

What I would add next

  • Memory and disk alarms, which need the CloudWatch agent
  • Alerts routed to PagerDuty or Slack
  • Composite alarms to cut noise
