VPC as code

An AWS network built from nothing in Terraform. One command creates it and one command removes it.

Built with
Terraform, VPC, subnets, internet gateway, route tables, security groups, EC2 (Amazon Linux 2023)
View the code on GitHub

How it works

  1. Terraform creates a VPC with the address range 10.0.0.0/16 in the London region.
  2. It adds a public subnet (10.0.1.0/24) and a private subnet (10.0.2.0/24).
  3. An internet gateway is attached to the VPC, and a route table sends 0.0.0.0/0 from the public subnet to it.
  4. A security group allows HTTP in from anywhere and SSH in from one address range that I pass in as a variable.
  5. One EC2 instance launches in each subnet to show the difference in reach.

Why I built it

Networking is the part of AWS that catches most people out, so I built a VPC from scratch instead of using the default one. Writing it as code made me work out how subnets, route tables and gateways relate, because Terraform will not let you skip a step.

What I learned

  • A subnet is public only because its route table points at an internet gateway. The name means nothing.
  • A security group is stateful and works at the instance. A network ACL is stateless and works at the subnet.
  • Terraform state tracks the real infrastructure, which is why I run plan before every apply.

The route that makes a subnet public

resource "aws_route_table" "public" {
  vpc_id = aws_vpc.main.id
  route {
    cidr_block = "0.0.0.0/0"
    gateway_id = aws_internet_gateway.igw.id
  }
  tags = { Name = "public-rt" }
}

resource "aws_route_table_association" "public" {
  subnet_id      = aws_subnet.public.id
  route_table_id = aws_route_table.public.id
}

SSH is allowed only from an address range passed in as a variable, so the instance is never open to the whole internet. HTTP stays open because the public host is meant to be reachable.
