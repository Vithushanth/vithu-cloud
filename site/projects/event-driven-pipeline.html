Event-driven data pipeline

A pipeline that processes each file the moment it arrives, with no server waiting and no schedule to tune.

Built with
Lambda (Python 3.12), S3 event notifications, CloudWatch, AWS SAM
View the code on GitHub

How it works

  1. A file is uploaded to the incoming/ prefix of the bucket.
  2. S3 emits an ObjectCreated event, which invokes the Lambda function.
  3. The function reads the bucket name and key from the event and fetches the file.
  4. It parses the CSV and counts the rows and columns.
  5. It writes a JSON summary under processed/ and logs each step to CloudWatch.

Why I built it

In an event-driven design, work happens because something occurred, with no timer and no idle server. I built the simplest version of that pattern to understand the wiring: the shape of an S3 event, how it reaches Lambda, and what to do when a file is not what you expected.

What I learned

  • The structure of an S3 event payload and how to pull the bucket and key out of it.
  • Why the trigger is limited to one prefix and the output goes to another. Without that, the function would trigger itself in a loop.
  • Defensive coding in Lambda: unreadable files are logged and skipped so one bad upload does not stop the rest.

Limiting the trigger to one prefix

Events:
  FileUploaded:
    Type: S3
    Properties:
      Bucket: !Ref DataBucket
      Events: s3:ObjectCreated:*
      Filter:
        S3Key:
          Rules:
            - Name: prefix
              Value: incoming/

To try it: aws s3 cp sample.csv s3://YOUR_BUCKET/incoming/sample.csv, then look under processed/.

What I would add next

  • Processed records pushed into DynamoDB or a data warehouse
  • A dead-letter queue for files that fail
  • Fan-out to several processors with SNS or EventBridge
