Private photo-sharing site

A private site where two people upload, caption and comment on photos and videos. I run a personal copy with real users and real data. The public repository is the same code with the names, domain and settings removed.

Built with
CloudFront, CloudFront Functions, S3, API Gateway (HTTP API), Lambda (Node.js), DynamoDB, SNS, CloudFormation
View the code on GitHub

How it works

  1. Every request goes to CloudFront, where a CloudFront Function checks the sign-in before anything else happens.
  2. Page files come from one S3 bucket and photos and videos from another. Both block all public access and are readable only through origin access control.
  3. Requests to /api/* go to an HTTP API and a single Lambda function. CloudFront adds a secret header, and the function refuses any request without it, so the API cannot be called directly.
  4. To add a photo, the browser asks the function for a presigned URL and uploads the file straight to S3.
  5. Captions, albums, comments, notes and hearts are rows in one DynamoDB table.
  6. Deleting moves a photo to a bin. It can be restored for 30 days, then the function erases every stored version of the file.
  7. Before an upload, the browser fingerprints the photo so the site can warn when it is already in the album.
  8. When one person adds something, SNS sends the other a short email, at most once an hour.

The rebuild

The first version grew piece by piece. I replaced it with a single CloudFormation install while keeping every existing photo, video and caption.

  1. I took a full backup of the existing site and its media.
  2. I deployed the new stack, which uses the existing media bucket and table and never creates, changes or deletes them.
  3. I tested it on its CloudFront address, then switched the domain over.
  4. I removed the old distribution, sign-in function, API, Lambda functions and site bucket, so nothing was left running or billing.

Why I built it

I wanted somewhere private for photos that I control myself, and a project with real users and real data instead of a demo.

What I learned

  • CloudFront Functions run before the cache and the origins, which makes them a cheap place to put a sign-in in front of a whole site.
  • An origin secret header closes the back door. Without it, anyone who found the API address could skip the sign-in.
  • Presigned URLs let the browser upload straight to S3 while the bucket stays private.
  • Replacing a live system is mostly about order: back up, build alongside, switch, check, then remove the old parts.
  • Real users find problems that tests miss, such as a phone keyboard covering the caption box.

Sign-in at the edge

function handler(event) {
  var request = event.request;
  var auth = request.headers.authorization;
  if (!auth || auth.value !== 'Basic ${Token}') {
    return {
      statusCode: 401,
      statusDescription: 'Unauthorized',
      headers: { 'www-authenticate': { value: 'Basic realm="Album", charset="UTF-8"' } }
    };
  }
  if (request.uri.indexOf('/media/') === 0) {
    request.uri = request.uri.substring(6);
  }
  return request;
}

This is HTTP Basic sign-in with one shared login, which suits a site for two people. For more users I would move to Cognito.
